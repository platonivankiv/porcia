# POR-DESIGN-006 — семейные профили

Baseline: `3f53623`. Владелец согласовал перенос из `../porcia-design-001-prototype/por-design-006/` в Next.js. Коммит не создаётся.

## Согласованная реализация

- Цветной верх карточки: Oswald, имя, цель, возраст, явно выбранный 2D-персонаж или монограмма. Нижняя часть: реальные расчётные КБЖУ, один раскрываемый блок параметров/методики, метки аллергий, исключений и предпочтений. Значения макета не подставляются.
- Редактор: Основное / Активность / Питание. Все разделы остаются смонтированными; `hidden` не выключает их поля из FormData. Сохранение имени доступно из любого раздела. Ошибка открывает нужный раздел и фокусирует поле. Создание/редактирование/отмена и ошибки сохранения используют прежние callbacks/storage.
- Четыре цели представлены native radio с контуром selected и focus-visible. Набор массы, поддержание веса, похудение, рекомпозиция используют прежние значения модели и расчётчик. Половая категория для формулы не назначает аватар.
- Чекбоксы продуктов и удаляемые метки, свободный текст по строкам, отдельные аллергии/исключения/нравится/не нравится. Скрытие незаполненного раздела ограничений сохраняет черновик, как прежде. Автоматической проверки рецептов нет.
- Необязательный `FamilyMember.avatarId`: только `man`, `woman`, `child`. Native dialog позволяет вручную выбрать/снять персонажа. Изображения уже находятся в public/family, provenance и credits сохраняются. Ни имя, ни возраст, ни категория формулы не участвуют в выборе.
- Хранение остаётся `version: 2`, ключ `porcia.family`. Старые v1/v2 без поля загружаются прежним путём без записи при чтении. Парсер валидирует id, снятие выбора даёт undefined и удаляет поле при JSON.stringify. ID участника/домохозяйства не меняются; только короткая строка, без изображений. Неизвестные значения отклоняются без перезаписи исходной записи.
- Формулы, рецепты, продукты, навигация, POR-009, зависимости и SCSS не меняются. Все CSS-правила семейного интерфейса находятся в family.css; общие legacy-стили POR-009 не переписываются.

## Проверка

Существующие публичные границы: parseMemberForm; loadFamily/saveFamily/decodeFamilyDocument; SSR компонентов. Браузерные сценарии проверяют реальные DOM, localStorage, переходы, сохранение, отмену и ошибки в отдельном временном профиле, без доступа к пользовательским данным.

TDD: сначала падение при неизвестном avatarId, затем его проверка; падение сохранения выбранного/пустого avatarId, затем парсинг; падение контракта трёх разделов и radio-целей, затем перенос формы. Прежние проверки формул и storage сохраняются.

Независимый read-only review: `git diff 3f53623` и новые файлы; два отдельных направления Standards / Spec. Источник требований — этот документ и согласованный прототип.

## Результат и проверка

- `npm test`: **250/250**, 12 файлов. `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check` — успешно.
- Production-браузер: **24 проверки геометрии** (список, создание, редактирование, активность, питание, диалог аватара × 320/390/768/1440 px). Горизонтального переполнения и незагруженных видимых изображений нет. Дополнительно проверено длинное имя без пробелов на четырёх ширинах.
- Реальная форма: имя без других параметров сохраняется из каждого раздела; введённые значения сохраняются при переключениях; проверены редактирование, отмена, дробный вес, неверный ввод в скрытом разделе, живой/частичный расчёт и отсутствие взрослого расчёта для 12 лет.
- Аватар устанавливается вручную, сохраняется после перезагрузки, не зависит от имени/половой категории. Снятие выбора удаляет поле из JSON. ID участника остаётся прежним. Старый v2 без аватара загружается без переписывания; v1 покрыт существующими storage-тестами.
- Проверены чекбоксы и удаляемые метки, записи своими словами, сохранение черновика при скрытии ограничений. Каталог продуктов изначально закрыт, как в прототипе; при ошибке раскрывается, выбранные метки всегда видны.
- Ошибки localStorage: отказ чтения, переполнение при записи, повреждённая запись и повторное чтение. Исходная запись и введённые значения сохраняются. Браузер запускается в отдельном временном профиле; реальные пользовательские профили не читаются и не изменяются.
- Проверены native radio со стрелок, focus-visible, hover, reduced motion, Enter для раскрытия методики, native modal Escape/возврат фокуса. Enter на radio внутри диалога не отправляет внешний профиль; Enter на кнопке применения работает. Это поведение сначала проверено падающим браузерным сценарием, затем исправлено точечным preventDefault для Enter на input внутри dialog.
- Проверка видимого DOM-текста: минимальный измеренный контраст **6,86:1**, нарушений проверенных порогов AA не найдено. JS-исключений нет. Это целевые проверки приложения, не полный маркетинговый checker design-taste-frontend.
- После client navigation `/family` → каталог → рецепт работают ссылки и дробные порции. CSS легенды POR-009 до/после: `padding-top: 0px`, `font-weight: 600`; влияния семейного CSS нет.
