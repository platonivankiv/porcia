# POR-DESIGN-004 — страница рецепта

Владелец утвердил композицию изолированного `porcia-design-001-prototype/por-design-004/`. Baseline рабочего приложения: `9c2251e`. Макет — визуальный источник истины; прототипный JS не переносится в приложение. Коммит не создаётся.

## Граница и контракт

Только существующая страница рецепта: яркий hero с изображением A/v3, Oswald/Manrope и существующими токенами, КБЖУ одной базовой порции, ингредиенты со счётчиком порций слева и шаги справа. На mobile — последовательная композиция. Время показывается только при наличии, без обещания неизменного времени при масштабировании.

Существующий RecipePortions остаётся владельцем текстового ввода, разбора и вычисляемого результата. Hero передаётся из серверного RecipeDetails как ReactNode; вычисление не дублируется и не переносится в CSS/состояние профилей. Пустой/невалидный ввод удаляет старые ингредиенты и показатели, управление вводом и инструкции остаются доступными.

Видны состояния исходных продуктов и единицы. Выход готового блюда не вычисляется по сумме ингредиентов. Методика, полные КБЖУ выбранного объёма, КБЖУ компонентов, известные/неизвестные выходы и источники сохранены в раскрываемом блоке. Критическое предупреждение о готовности курицы и оговорка об аллергенах видны вне details.

POR-009 обёрнут в native details после основного содержания. Существующий FamilyRecipePortions не переписан: сохраняются загрузка семьи, ошибки/пустой список, коэффициенты компонентов, независимость от общего счётчика, предупреждение о черновике, ограничениях и аллергенной безопасности. Закрытие блока не размонтирует редактор и не стирает черновик.

Модели, каталог/составы, формулы, парсеры, алгоритмы, семейные профили, localStorage и зависимости не меняются. Новый CSS ограничен `.recipe-detail-app`, одно свойство на строку. Реорганизация старых стилей/SCSS отложена до POR-STYLE-001.

## Проверки

Границы TDD: публичный рендер RecipeDetails и существующие тесты калькуляторов/парсеров/POR-009. Новая проверка сначала падает на расположении счётчика/состояниях продуктов/закрытом POR-009, затем проходит. Подпись базовой порции уточняется без изменения математики.

Обязательные команды: npm test, npm run typecheck, npm run lint, npm run build, git diff --check. Production Chrome: три рецепта ×320/390/768/1440, целые/дробные/пустые/невалидные порции, аллергены, safety, источники, неизвестный выход, POR009, фокус, hover и reduced motion. Неизвестные пищевые данные и изображение проверяются через существующий публичный рендер с изолированными входными fixtures, без правок каталога.

Независимый read-only review: Standards и Spec; весь diff от baseline плюс новые файлы.

### Результат

- `npm test`: 242 теста в 12 файлах. `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check` — успешно.
- Production Chrome: все три рецепта, 36 проверок геометрии на 320/390/768/1440 px, включая открытые источники и POR-009. Горизонтального переполнения нет. Изображения загрузились, шрифты/контуры соответствуют A/v3.
- Проверены 4 и 1,25 порции, пустой/нулевой/невалидный ввод и восстановление, удаление старых результатов, молоко/грецкие орехи, видимая safety-информация 74 °C при ошибке ввода, источники и неизвестный выход готового блюда.
- POR-009: коэффициенты 0,5/0/невалидное значение, красная рамка ошибки, независимость от общего счётчика, сохранение черновика при закрытии/открытии native details. Для проверки создан вымышленный участник через реальную форму в отдельном временном Chrome; пользовательское хранилище не затронуто.
- Изолированные SSR fixtures настоящего RecipeDetails с пустым справочником и отсутствующими фото/временем открыты в браузере на всех четырёх ширинах. Не показываются выдуманные КБЖУ, изображения и время; safety остаётся видимой. Рабочий каталог и production-маршруты для проверки не менялись.
- Focus-visible 3 px, hover и reduced motion проверены. Проверка контраста видимого текста основных страниц соответствует AA. Полный marketing gate не заявляется: структура лендинга противоречит утверждённому продуктовому макету.
- Два независимых read-only reviewer завершили повторную проверку без открытых замечаний. Исправлены каскад error-border POR-009 и скрытие принудительного переноса подписи КБЖУ до 1150 px; подтверждены реальными computed styles браузера.
- Production-снимки, изолированные fixtures, браузерные JSON-отчёты и сравнение с прототипом сохранены вне репозитория в `porcia-design-001-prototype/previews/POR-DESIGN-004-*`; страница просмотра — `POR-DESIGN-004-implementation.html`.
- Формулы, парсеры, модели, каталог, FamilyRecipePortions, семейные профили, storage, зависимости и общие стили не изменены. Коммит не создан. Реорганизация CSS/SCSS остаётся отдельной задачей POR-STYLE-001.
