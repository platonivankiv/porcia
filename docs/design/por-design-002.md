# POR-DESIGN-002 — A/v3, этап 1

Утверждено владельцем 25 ноября 2026 года. Источник: изолированный `porcia-design-001-prototype`, `v3.html`, `v2.css` + `v3.css`, утверждённые изображения из `assets/v2/`. Исходная точка рабочего дерева: `5aad48d`; коммит в этой задаче не создаётся.

## Контракт этапа

- Локальные Oswald Bold 700 для акцентных заголовков и Manrope для текста. Встроенный `next/font/local`, без новых npm-зависимостей и сетевых запросов к Google Fonts при сборке или показе страницы.
- Токены A/v3: фон `#fff8ef`, поверхность `#fffdfa`, текст/рамки `#20251f`, вторичный текст `#51584e`, зелёный `#16cc68`, лавандовый `#c6a0f5`, коралловый `#ff8b7c`, жёлтый `#ffda5c`.
- Крупные карточки 3 px, кнопки и навигационные элементы 2 px. Мелкие метки и разделители тоньше.
- Общая навигация: боковая на desktop, верхняя на mobile. Только `/recipes` и `/family`, рабочий skip link, активный раздел. `/` не перенаправляется.
- `/recipes`: одна общая сетка, цветные карточки, целые вырезанные блюда, крупное название, категория, известное время, калорийность на **1 базовую порцию**. Длинные описания остаются в рецепте. Число исходных порций остаётся доступно вспомогательным технологиям, в том числе для дробного базового объёма.
- В каталоге подключаются утверждённые прозрачные WebP с новыми `-cutout` URL; прежние файлы оставлены для совместимости ссылок и разделения кеша оптимизатора. Сохраняются AI-маркировка, ссылка на credits и полные промпты. Модели, составы и расчётчики не меняются.
- Сохраняются пустой каталог, отсутствие фото, недоступные КБЖУ и существующие переходы. Отсутствие данных не выдаётся за ноль.

## Граница

Общие шрифты, фон и навигация применяются к существующим экранам. Страницы отдельных рецептов, форма/профили семьи, модели, расчёты и localStorage не переписываются. Их содержимое сохраняет текущие компоненты и старые контрастные кнопки; полноценный редизайн этих экранов — следующие этапы. В частности, чекбоксы вместо select multiple, персонажи и изменения POR-009 сюда не входят. Универсальная UI-библиотека, готовые рационы, планировщик и покупки не создаются.

## Проверки и review

Наблюдаемые границы: рендер каталога/навигации, существующие расчётчики, состояние ввода и storage. Для новых контрактов — red → green тесты рендера; существующие доменные и семейные тесты сохраняются.

Обязательны `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check`. В браузере: сравнение A/v3 на 1440/390 px, отсутствие переполнения на 320/390/768/1440, кириллица/длинные названия, изображения/ссылки, контраст, hover/focus/reduced motion, smoke-проверка существующих рецептов и семейной формы.

Независимый review сравнивает весь рабочий diff с `5aad48d` (включая новые файлы), отдельно по стандартам AGENTS.md и по этому контракту/запросу владельца. Без правок со стороны reviewer и без коммита.

### Результат проверки

- `npm test`: 236 тестов в 12 файлах; `npm run typecheck`, `npm run lint`, `npm run build`, `git diff --check` — успешно.
- Production-снимки каталога на 320/390/768/1440 px и сравнение desktop/mobile с исходным A/v3 сохранены вне рабочего приложения, в `porcia-design-001-prototype/previews/POR-DESIGN-002*`.
- В изолированном Chrome подтверждены загрузка трёх изображений, переходы, отсутствие горизонтального переполнения каталога, семьи и рецепта на всех четырёх ширинах. Создание, сохранение, перезагрузка и отмена редактирования вымышленного профиля работают; пользовательское хранилище не затрагивалось. Проверены целые, дробные, пустые и невалидные порции и восстановление расчёта.
- Целевые browser-checks для hover, focus-visible, контраста, загрузки шрифтов, обрезания/перекрытия текста и reduced motion прошли. Общий marketing-checker не используется как итоговый gate: его требования к полноэкранным hero/секциям не применимы к этому продуктовому каталогу.
- Независимые read-only review стандартов и спецификации завершены без открытых замечаний. Найденное ограничение ширины общей навигации из-за старого класса контейнера устранено и повторно проверено обоими reviewer.
- Следующие этапы: представление отдельного рецепта, семейные карточки/персонажи и формы, второстепенный интерфейс ручных порций POR-009. Бизнес-правила и будущие функции не входят в этот перенос.
