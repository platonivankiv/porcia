# Porcia — пользовательские сценарии

Статус: основной сценарий обновлён по POR-010 23 ноября 2026 года; планирование ещё не реализовано. Текущие сценарии профилей POR-008 и ручных черновиков порций POR-009 описаны ниже. Обязательные требования и границы готовности находятся в [requirements.md](requirements.md), термины — в [глоссарии](../../GLOSSARY.md).

## Основной сценарий: готовый рацион → план семьи

1. Пользователь создаёт семью и добавляет участников. Для сохранения участника достаточно имени.
2. Заполняет параметры для автоматических дневных КБЖУ. Если расчёт недоступен или частичен, приложение объясняет причину и не подставляет недостающие показатели.
3. Открывает каталог карточек готовых рационов на несколько дней. Видит конкретные блюда, ориентировочное общее время приготовления и особенности меню.
4. Выбирает понравившийся рацион. Его набор блюд сохраняется: приложение не заменяет их автоматически.
5. Приложение автоматически рассчитывает индивидуальные количества продуктов через масштабирование компонентов. Показывает понятные граммовки и состояния продуктов, а не коэффициенты базовых порций. Строгие ограничения и аллергии учитываются как обязательные условия.
6. Если точное попадание в КБЖУ невозможно, пользователь видит отклонения и предложенные варианты; изменение блюд требует его подтверждения. Недостаточность данных не скрывается за вымышленным полным результатом.
7. Получает персонализированный план: меню, инструкции приготовления и распределение еды между участниками. Масса готовой еды показывается только при известном применимом выходе; исходные граммовки не выдаются за готовый вес.
8. Может изменить количества, заменить блюдо или создать собственный рацион. План пересчитывается без скрытого изменения других назначений; исходный шаблон готового рациона сохраняется. Поддерживаются перекусы, сладости, напитки и продукты без рецептов.
9. В будущем получает общий список покупок. Наличие меню на несколько дней само по себе не подтверждает допустимость хранения приготовленной еды весь этот период.

Каталог, автоматическая адаптация и план приготовления — будущие задачи. POR-010 фиксирует концепцию и упрощает профиль, сохраняя текущий интерфейс POR-009.

## Дополнительный сценарий: собственное меню → будущие покупки

1. Пользователь выбирает период и участников семьи, указывает ограничения и привычки питания.
2. Добавляет блюда и продукты без рецепта в нужные приёмы пищи. Перекус или напиток не требуют создания рецепта.
3. Назначает участникам количества компонентов и продуктов; видит КБЖУ по приёмам пищи и дням.
4. Определяет приготовления для нескольких дней, быструю сборку перед едой и позиции без приготовления. Применимость хранения проверяется по известным правилам; при недостатке данных система не подтверждает безопасность выбранного интервала.
5. Получает общий объём каждого приготовления и единый список покупок на все назначения периода.
6. Указывает, что уже есть дома, видит оставшееся количество покупки по категориям и отмечает купленное.
7. При изменении меню получает пересчитанную потребность. Изменения относительно уже купленного должны быть понятны; конкретное поведение отметок ещё предстоит согласовать.

Это один законченный сценарий. Проверка только выбора блюд или только одного дня не подтверждает его готовность.

## Повторная адаптация → подтверждение → ручная правка

1. Пользователь явно запрашивает новый расчёт количеств выбранного рациона.
2. Приложение показывает предложенные количества и отклонения от дневных КБЖУ. Выбранные блюда автоматически не заменяются.
3. Если нужны изменения меню, пользователь рассматривает варианты и подтверждает конкретные замены. Порядок принятия предложения поверх ручных правок согласуется до реализации.
4. После принятия обновляется план семьи, а исходный шаблон рациона сохраняется. Рекомендованные, плановые и фактически съеденные количества различаются.

## Пример: меньше риса, печенье вечером

Участник уменьшает только рисовый компонент обеда и добавляет конкретное печенье в вечерний перекус. Пересчитываются дневные энергия и БЖУ, объём риса и покупки. Количества курицы, овощей и других блюд не меняются автоматически; исходная рекомендация остаётся прежней. Масса готового риса не выводится из сухой без подходящего выхода.

## Готовка, сборка и факт

Для заранее готовящегося блюда пользователь видит запланированный объём и применимые условия хранения. Быстрый йогуртовый завтрак собирает перед едой, готовый упакованный продукт использует без создания приготовления рецепта. Покупки охватывают все три случая.

Когда появится учёт факта, пользователь сможет уточнить приготовленную партию и съеденные количества. Такая запись изменяет фактическое потребление, сохраняя первоначальный план и рекомендацию. Для продукта без рецепта факт относится к выбранному продукту, а не к вымышленной приготовленной партии.

## POR-009: рецепт → ручные порции семьи

1. Пользователь открывает рецепт и блок «Порции семьи». При отсутствии участников переходит к созданию профилей в `/family`; ошибки чтения не заменяются пустой семьёй.
2. Читает состав одной базовой порции каждого компонента: исходные количества и состояния продуктов. Например, 1 порция риса соответствует 80 г сухого риса, без утверждения массы после приготовления.
3. Выбирает участников и вручную заполняет каждому все компоненты. Поля изначально пустые; 0 исключает компонент из назначения, дроби с запятой или точкой задают его количество.
4. Видит мгновенно пересчитанные КБЖУ каждого заполненного участника и суммарные исходные ингредиенты после заполнения всех выбранных участников. Изменение риса не меняет другие компоненты или назначения.
5. При пустом или неверном вводе соответствующие полные итоги недоступны до исправления. Дневные ориентиры и отдельный общий калькулятор порций остаются прежними.
6. После перезагрузки назначения сбрасываются. Меню, покупок и автоматического назначения нет; ограничения автоматически не проверяются. [Контракт POR-009](recipes/por-009.md).

## POR-008 / POR-010: профиль → автоматические ориентиры

1. Пользователь открывает `/family` и создаёт либо редактирует участника на той же странице. Для сохранения достаточно имени; автоматических тестовых профилей нет.
2. Для расчёта заполняет возраст, рост, вес, половую категорию уравнения, активность, тренировочный контекст и цель. Имя и поля для расчёта отмечены звёздочками. Только имя обязательно для сохранения. Остальные отмеченные поля необходимы для автоматического расчёта, но их заполненность не гарантирует доступность результата. Вопросов о беременности, лактации и медицинских обстоятельствах нет.
3. Результат обновляется сразу при изменении полей, без кнопок расчёта, принятия или ручного редактирования КБЖУ. Частичный и недоступный результаты объясняются; недостающие значения не выдумываются. Рядом с результатом указано: «КБЖУ — расчётные ориентиры. Они не учитывают индивидуальные медицинские обстоятельства».
4. Пользователь заполняет ограничения и предпочтения. Автоматической проверки рецептов по ним пока нет.
5. Сохраняет параметры профиля или отменяет черновик. После перезагрузки рекомендации заново вычисляются из сохранённых параметров.
6. Ошибка записи оставляет форму заполненной. Повреждённые данные не перезаписываются автоматически. v1 мигрируется без потери участников, а старые ручные КБЖУ остаются только в архиве. В новых профилях удалённых ответов нет; в старых v2 они могут сохраняться исключительно для совместимости и не влияют на расчёт.

Это временный браузерный прототип для вымышленных данных, без аккаунта и доступа с других устройств. [Контракт POR-008](family/por-008.md). [Исторический контракт POR-007](family/requirements.md).
